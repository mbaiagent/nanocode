# 提交信息规范

## 步骤
1. 运行 `git diff --staged` 查看暂存的改动；如果没有暂存内容，运行 `git status` 并询问用户要提交哪些文件。
2. 判断改动类型：feat（新功能）/ fix（修 bug）/ refactor（重构）/ docs（文档）/ test（测试）/ chore（杂项）。
3. 按下面的格式写提交信息，用中文。

## 格式
```
<类型>: <一句话描述，不超过 50 字>

<可选：为什么要改，改了什么，2~4 行>
```

## 例子
```
fix: 修复登录 token 过期后不刷新的问题

过期判断使用了本地时间，时区不同时会提前失效。
改为使用服务器返回的 expires_at。
```

不要在提交信息里写"由 AI 生成"之类的内容，除非用户要求。
