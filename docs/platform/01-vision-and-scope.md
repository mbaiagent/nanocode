# 01 愿景与范围

## 一、要做的是什么

一个**能替人完成多步骤工作的 Agent 平台**：用户用自然语言交代任务，Agent 自己规划、调用工具、访问企业数据和外部系统、执行代码或操作网页，在需要时请人确认，最后交付结果。

它分两条产品线，共用一个平台底座：

| 产品线 | 用户 | 典型任务 | 关键要求 |
|---|---|---|---|
| **企业 Agent 平台** | 企业员工、IT 和业务团队、开发者 | 写代码和修 bug；分析数据出报表；处理工单、合同、报销；跨系统查资料写方案；定时巡检和汇总 | 接企业系统和数据、按权限访问、审批与审计、合规认证、私有化部署 |
| **通用 Agent** | 个人用户、小团队 | 调研写报告、订行程、整理文件、做网页和小工具、操作网站完成事务 | 开箱即用、响应快、便宜、安全、防滥用 |

编程 Agent（nanocode 的定位）是两条产品线里的一个**场景**，不是全部。

## 二、核心能力

平台必须提供的能力，按"没有就不能用"到"有了更好"排序：

1. **可靠地完成多步骤任务**：任务能持续几分钟到几天；中途机器故障、网络中断、用户关掉页面都不丢进度。
2. **安全地使用工具**：执行代码、操作浏览器、调用外部系统都在隔离和授权范围内；高风险操作有人把关。
3. **按权限使用企业数据**：Agent 只能看到发起人本来就有权看到的数据。
4. **可管、可审、可控成本**：管理员能设置策略、配额、可用模型和工具；所有操作留痕；成本可预测。
5. **可扩展**：企业和第三方能自己接入工具、知识和 Agent 定义。
6. **多端与多入口**：网页、移动端（iOS、Android）、PC 端（桌面应用、命令行、IDE 插件）、IM（企业微信、钉钉、飞书、Slack）、API、定时和事件触发。同一个任务可以跨端接续：电脑上发起、手机上审批、回到电脑看结果。见 [13 多端客户端](13-multi-device-clients.md)。
7. **多模态**：读写文档、表格、图片、语音，操作图形界面。

## 三、不做什么（非目标）

明确不做的事和做之前需要单独立项的事：

- **不做通用基础大模型的训练**（L1、L2）。模型从厂商采购或部署开源模型；L3 时这一条要重新评估，见 [12 架构决策记录](12-adr.md) ADR-007。
- **不替代企业现有的业务系统**：Agent 调用 CRM、ERP、工单系统，不复制它们的功能。
- **不承诺完全无人值守的高风险操作**：付款、删除生产数据、对外发送正式文件等，默认必须有人审批，企业可以按策略调整，但平台不提供"关闭所有审批"的全局开关。
- **L1 阶段不做开放的工具市场**：先支持企业自有和平台认证的连接器，开放生态放到 L2。

## 四、规模档位与目标

### 估算方法

```
高峰同时运行的任务 ≈ 用户数 × 日活比例 × (每人每天使用分钟 ÷ 1440) × 高峰系数
高峰模型调用 / 秒  ≈ 同时运行的任务 ÷ 每次调用的间隔秒数
高峰输入 token / 秒 ≈ 模型调用 / 秒 × 每次调用的平均输入 token
```

### 三个档位

| | L1 | L2 | L3 |
|---|---|---|---|
| 用户数 | 1 千 – 10 万 | 1000 万 | 10 亿 |
| 日活比例 | 30%–60%（企业内部） | 15% | 20%–30% |
| 每人每天使用 | 30–60 分钟 | 30 分钟 | 10–20 分钟，大部分是轻量对话 |
| 高峰同时运行任务 | 100 – 1 万 | 5 万 – 10 万 | 千万级会话 |
| 其中需要执行环境的 | 大部分（编程、数据分析） | 30%–60% | 少数（10% 以内） |
| 高峰输入 token / 秒 | 20 万 – 3000 万 | 约 1.5 亿 | 百亿级 |
| 典型客户 | 一家大企业内部，或几十家企业 | 几万家企业 + 大量专业个人用户 | 所有人 |
| 部署 | 一个区域，一到几个单元 | 多个区域，几十到上百个单元 | 全球几十个区域，自建数据中心 |

L1 的范围很宽（一千到十万），是因为企业内部平台通常从一个部门试点开始，再推广到全公司。架构上 L1 用同一套设计，只是单元数量不同。

### 每档的成功指标

| 指标 | L1 | L2 | L3 |
|---|---|---|---|
| 任务成功率（评测集 + 线上抽样） | ≥ 70%，并逐季提升 | ≥ 80% | 简单任务 ≥ 95%，复杂任务 ≥ 80% |
| 平台可用性 | 99.5% | 99.9% | 99.95%（核心对话） |
| 首字延迟 p95 | < 5 秒 | < 3 秒 | < 1.5 秒 |
| 执行环境就绪 p95 | < 10 秒 | < 2 秒 | < 500 毫秒（轻量执行） |
| 单个任务平均成本 | 可计量、可按部门分摊 | 低于定价的 40% | 低于定价的 30%，免费用户成本可控 |
| 安全 | 零跨租户数据泄露 | 同左 + 通过 SOC 2 Type II、ISO 27001 | 同左 + 各主要市场的监管要求 |

## 五、典型场景（用于验证设计）

每篇设计文档都应该能说明这些场景在自己负责的部分怎么跑通。

| 编号 | 场景 | 考验的能力 |
|---|---|---|
| S1 | 开发者让 Agent 修一个 bug，跑测试，提交 PR | 代码执行沙箱、git 凭证、自动验证 |
| S2 | 分析师上传数据，让 Agent 清洗、分析、出图表报告 | 数据处理执行环境、大文件、制品 |
| S3 | 员工问"我们和 A 公司的合同里违约条款怎么写的，和最新模板有什么不同" | 企业知识检索、**权限过滤**、引用来源 |
| S4 | 每天早上 8 点汇总昨天的工单、告警和销售数据，发到群里 | 定时触发、多连接器、无人值守运行、发送前的策略检查 |
| S5 | 让 Agent 在供应商网站上下单采购（金额超过阈值需审批） | 浏览器操作、审批流、长时间等待、凭证安全 |
| S6 | 一个持续三天的调研任务：收集资料、多个子 Agent 分头分析、汇总报告 | 长时间运行、多 Agent、断点恢复、成本上限 |
| S7 | 个人用户让通用 Agent 规划旅行并比价 | 网页浏览、低成本、快速响应、防滥用 |
| S8 | 一家银行要求全部数据不出内网 | 私有化部署、离线模型、合规审计 |
| S9 | 在电脑上让 Agent 整理本地项目并发周报，下班路上在手机上批准发送；电脑合上后剩余步骤改到云端继续 | 跨端接续、执行位置动态调整、移动端推送与审批 |
| S10 | 个人用户在手机上拍下发票，让 Agent 报销并加到日历提醒 | 移动端拍照输入、手机系统能力工具、连接器 |

## 六、主要约束与假设

- **模型能力在持续变化**：平台不能绑定某一家模型的特性，要能在几天内切换或混用模型。
- **模型成本是最大的可变成本**：在 L2、L3，推理成本可能占总成本的大部分，架构和定价都要围绕它设计。
- **Agent 会犯错，也会被攻击**：提示词注入无法从模型层面彻底解决，安全必须依赖隔离、权限和审批，而不是依赖模型"听话"。
- **企业客户的采购决定于合规和集成**，而不只是能力：没有 SSO、审计、私有化选项，大企业基本不会采购。
- **监管在快速变化**：各国关于生成式 AI、数据跨境、算法备案的要求不同，合规能力需要按区域可配置。
