# Agent 平台设计文档集

这组文档回答一个问题：**如果把 nanocode 这样的编程 Agent，发展成企业级、乃至面向所有人的通用 Agent 平台，并支撑从一千到十亿用户的规模，需要怎样的产品范围、架构、设计和实施计划。**

它和 [第 12 章](../12-distributed-deployment.md) 的关系：第 12 章只讨论"把现在的编程 Agent 部署给 1000 人用"；这组文档把范围扩大到**企业级平台**和**通用 Agent**，规模扩大到千万和十亿。第 12 章的方案就是这里规模档位 L1 的一个特例。

> 所有容量、成本、工期、团队规模都是**数量级估算**，用来判断瓶颈和排优先级。每一档开工前都要用压测、试点数据和真实报价替换。

## 规模档位

全部文档统一用这三个档位描述规模，每一档的瓶颈不同，架构也不同。

| 档位 | 用户规模 | 典型形态 | 高峰同时运行的任务 | 高峰模型输入 token / 秒 | 主要矛盾 |
|---|---|---|---|---|---|
| **L1** | 1 千 – 10 万 | 企业内部平台、少数企业客户 | 100 – 1 万 | 20 万 – 3000 万 | 隔离、多租户、企业集成与合规 |
| **L2** | 1000 万 | 面向大量企业和专业用户的 SaaS | 5 万 – 10 万 | 约 1.5 亿 | 推理成本、执行算力、多地区、数据分片、防滥用 |
| **L3** | 10 亿 | 面向所有人的通用 Agent | 千万级会话（其中需要执行环境的是少数） | 百亿级 | 算力和电力本身、自研模型、全球合规与运营 |

估算假设（L2）：日活 15%，每人每天使用 30 分钟，高峰是平均值的 2–3 倍，运行中的任务每 20 秒左右调用一次模型、每次输入约 3 万 token。L1、L3 的估算方法相同，见 [01 愿景与范围](01-vision-and-scope.md#四规模档位与目标)。

## 术语表

| 术语 | 含义 |
|---|---|
| 组织（Org / 租户） | 付费和管理的单位，一家企业或一个个人账号。隔离、配额、策略都以它为边界 |
| 工作空间（Workspace） | 组织内的协作单位（团队、项目），有自己的成员、Agent、知识库和连接器 |
| Agent 定义 | 一个可复用的 Agent 配置：系统提示词、可用工具、模型、策略、知识范围。相当于 nanocode 的"技能 + 配置"的平台化版本 |
| 会话（Session） | 用户和 Agent 的一段对话，包含多次任务 |
| 运行（Run） | 一次任务执行，从用户输入到 Agent 给出最终结果。可能持续几秒，也可能几天 |
| 步骤（Step） | 运行里的一次模型调用或一次工具调用，是**持久化和恢复的最小单位** |
| 工具（Tool） | Agent 能调用的能力：执行代码、搜索、读写文件、调用外部 API 等 |
| 连接器（Connector） | 接入外部系统（邮件、文档、IM、CRM、数据库）的工具集合，通常基于 MCP |
| 执行环境（Sandbox） | 执行代码、操作浏览器或桌面的隔离环境 |
| 制品（Artifact） | 运行产出的文件、报告、代码改动、网页等 |
| 记忆（Memory） | 跨会话保留的信息：用户偏好、组织约定、经验 |
| 审批（Approval） | 高风险操作执行前，需要人确认的环节。nanocode 的权限确认的平台化版本 |
| 单元（Cell） | 一套完整、独立的服务部署，服务一部分租户。故障不会扩散到其他单元 |
| 区域（Region） | 一个地理区域里的一组单元，满足数据驻留要求 |

## 平台组件名称

各篇文档统一使用以下名称（详见 [02 总体架构](02-architecture.md)）：

接入网关、控制面、编排服务、Agent Worker、执行服务、模型网关、推理集群、知识服务、连接器中心、凭证保险库、策略引擎、事件总线、审计服务、计量计费、可观测性平台、管理后台。

## 和 nanocode 代码的对应关系

nanocode 的每个模块，在平台里都有一个"放大版"。读 nanocode 的代码，可以帮助理解平台里对应组件要解决的核心问题。

| nanocode | 平台组件 | 放大后多出来的问题 |
|---|---|---|
| `agent.py` Agent 循环 | 编排服务 + Agent Worker | 崩溃恢复、长时间运行、并发、多 Agent 协作 |
| `tools/` 内置工具 | 工具运行时 + 执行服务 | 隔离、资源调度、成本 |
| `permissions.py`、`risk.py`、`review.py` | 策略引擎 + 审批 | 组织级策略、审批流、合规留痕 |
| `hooks.py` | 策略引擎的扩展点、事件订阅 | 多租户隔离、可靠投递 |
| `mcp.py` | 连接器中心 | 代表用户的授权、凭证管理、大规模连接器运维 |
| `rag.py` | 知识服务 | 海量数据、增量同步、**按权限过滤检索结果** |
| `context.py` 上下文与记忆 | 上下文管理 + 记忆服务 | 跨会话、跨用户、隐私 |
| `llm/` 模型适配 | 模型网关 + 推理集群 | 路由、限流、成本、多厂商、自建推理 |
| `events.py` 事件总线 | 事件总线（Kafka 类）+ 可观测性 | 可靠投递、回放、海量数据 |
| `verify.py`、`subcheck.py`、`lessons.py` | 质量与评测体系 | 线上质量监控、评测驱动的发布 |
| `trust.py` | 策略引擎 + 租户配置 | 谁有权决定什么、管理员策略 |
| `web/server.py` | 接入网关 + 控制面 + 前端 | 身份认证、海量长连接、多端 |
