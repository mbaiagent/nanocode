# 10 交付形态与商业化

## 一、交付形态

| 形态 | 说明 | 适合 | 平台要求 |
|---|---|---|---|
| **多租户 SaaS** | 共享单元，逻辑隔离 | 中小企业、个人用户、大部分团队 | 标准能力 |
| **专属单元** | 客户独占一个或多个单元，独立数据库和密钥，仍由平台运维 | 大型企业、对隔离有要求的客户 | 单元可按客户创建；客户自管密钥 |
| **客户云内部署（BYOC）** | 数据面部署在客户自己的云账号里，控制面由平台托管 | 数据不能离开自己云账号的客户 | 控制面与数据面分离；数据面只出站连接控制面 |
| **私有化部署** | 全部部署在客户机房或私有云，可以完全断网 | 金融、政府、军工、对数据极敏感的客户 | 所有依赖有开源替代；离线安装和升级；可接客户自己的模型 |

设计约束（见 [02 总体架构](02-architecture.md#七技术选型原则)）：私有化部署要用**同一套代码**，只是部署和依赖替换不同，否则会分裂成两个产品，维护成本翻倍。

私有化部署的难点不在安装，而在**模型**：客户机房里往往只能用开源模型，能力可能不如公有云的大模型。需要针对开源模型调整提示词和 Agent 定义，并用评测确认效果。

## 二、管理后台

企业管理员需要的功能：

| 模块 | 功能 |
|---|---|
| 成员与权限 | SSO 和 SCIM 配置、角色分配、组管理 |
| Agent 管理 | 组织内可用的 Agent 定义、发布审核、版本管理、使用统计 |
| 连接器 | 允许使用的连接器白名单、服务账号、企业内网网关状态 |
| 知识 | 知识源配置、同步状态、权限同步状态、检索质量评测 |
| 策略 | 可用模型、可用工具、审批规则、出口白名单、数据防泄漏规则、数据保留期 |
| 用量与成本 | 按部门、用户、Agent 的用量和成本；预算设置；分摊报表 |
| 审计 | 查询、导出、推送到 SIEM；运行回放 |
| 合规 | 数据驻留、数据导出和删除请求、合规报告 |

## 三、定价

模型成本和用量强相关，定价必须让收入和成本同向变化。

| 模式 | 做法 | 适合 | 风险 |
|---|---|---|---|
| 按席位订阅 | 每人每月固定费用 | 企业采购习惯 | 少数重度用户的成本可能远超席位费 → 必须有用量上限或公平使用条款 |
| 席位 + 用量包 | 席位包含一定额度，超出按量计费或购买额度包 | **推荐的企业默认方案** | 需要清晰的用量展示，避免账单意外 |
| 按量计费 | 按运行、按 token 或按"任务点数"计费 | API 和开发者客户 | 客户难以预测成本 → 提供预算上限 |
| 按结果计费 | 按完成的工单、生成的报告计费 | 特定场景的成熟 Agent | 需要可靠地判断"完成" |
| 免费 + 付费档位 | 免费档严格限额，付费档提高额度和能力 | 个人用户（L2、L3） | 免费用户的成本和滥用 → 免费档不提供或严格限制执行环境 |

### 单位经济模型

```
每活跃用户每月毛利 = 每用户每月收入 − (模型成本 + 执行环境成本 + 存储成本 + 连接器成本 + 支持成本)
```

L2 起，这个公式必须按用户分层（轻度、中度、重度）计算。Agent 产品的用量分布通常非常不均匀，少数重度用户可能贡献大部分成本。

## 四、计量计费

- **计量单位**：模型 token（按模型档位加权）、执行环境时长（按级别加权）、存储、连接器调用；对用户可以统一折算成"点数"，降低理解成本。
- **实时扣减**：运行前检查剩余额度，运行中按步骤扣减（模型网关和执行服务上报），额度耗尽时运行暂停并提示，而不是事后出现超额账单。
- **对账**：计量数据和模型厂商账单、云账单定期核对。
- **透明**：用户能看到每次运行花了多少；管理员能看到部门和个人明细。

## 五、客户成功

企业客户能否持续使用，取决于上线后的效果：

- **上线辅导**：帮助客户识别高价值场景、配置知识源和连接器、编写 Agent 定义。
- **场景模板**：常见场景（工单处理、销售助理、代码审查、周报汇总）的现成 Agent 定义。
- **效果度量**：给客户的价值报告（完成了多少任务、节省了多少时间、成功率）。
- **反馈闭环**：客户反馈进入评测集和改进计划。
