# 13 多端客户端：云端、移动端、PC 端

用户会同时使用三类终端：**网页（云端）**、**移动端**（iOS、Android）、**PC 端**（桌面应用、命令行、IDE 插件）。同一个用户经常跨端：在电脑上发起任务，在手机上看进度、批准操作，回到电脑上看结果。

三类终端的能力差别很大，尤其是**能不能在本机执行**。本篇说明：会话在哪里、执行放在哪里、各端分别做什么、怎么跨端接续、怎么保证设备安全。

## 一、核心原则

1. **会话和运行在云端，终端是"视图"和"执行节点"**：运行的状态始终在编排服务里（见 03），任何终端都只是查看和操作它的入口。所以换设备、断网、关机都不会丢失运行。
2. **执行位置按"这一步需要什么"和"现在有哪些设备在线"动态决定**，而不是固定在某一端。见 ADR-011。
3. **能力按端降级，体验按端优化**：所有端都能对话、看进度、审批、看结果；只有具备条件的端才承担本地执行。
4. **设备是需要信任管理的主体**：设备注册、设备凭证、丢失时远程撤销，和用户身份一样管理。

## 二、终端能力矩阵

| 能力 | 网页 | 移动端 iOS | 移动端 Android | PC 桌面应用 / 命令行 / IDE |
|---|---|---|---|---|
| 对话、查看进度、查看制品 | ✓ | ✓ | ✓ | ✓ |
| 审批 | ✓ | ✓（生物识别确认） | ✓（生物识别确认） | ✓ |
| 后台接收通知 | 仅页面打开时（浏览器推送需授权） | ✓ 系统推送 | ✓ 系统推送 | ✓ |
| 语音、拍照、相册、位置作为输入 | 部分 | ✓ | ✓ | 部分 |
| 访问本地文件 | 仅用户选择的单个文件 | 仅应用沙箱和用户选择的文件 | 仅授权的目录 | ✓ 授权的工作目录 |
| **执行任意代码和命令** | ✗ | ✗（应用商店对下载并执行代码有严格限制） | 受限（且应用商店政策限制） | ✓ |
| 操作本机图形界面 | ✗ | ✗ | 受限（无障碍服务，商店政策严格） | ✓（需明确授权和可见提示） |
| 使用用户已登录的浏览器 | ✗ | ✗ | ✗ | ✓（浏览器插件或本机浏览器） |
| 调用系统能力作为工具（日历、通讯录、提醒、健康等） | ✗ | ✓（逐项系统授权） | ✓（逐项系统授权） | 部分 |
| 端上小模型 | 有限（WebGPU） | ✓ | ✓ | ✓ |
| 长时间后台运行 | ✗ | ✗（系统严格限制后台） | 有限 | ✓（常驻进程） |
| 典型网络 | 企业网络、可能只开放 443 | 移动网络，会切换、会断 | 同左 | 稳定，可能有企业代理 |

由此得到各端的定位：

| 终端 | 定位 | 执行在哪里 |
|---|---|---|
| **网页** | 全功能入口，无需安装；企业员工、临时使用 | 全部在云端 |
| **移动端** | 随时发起、跟进、审批；语音和拍照输入；调用手机上的个人数据和系统能力 | 云端执行 + 手机系统能力类工具在本机 |
| **PC 端** | 深度工作：编程、处理本地文件、操作本机应用和已登录的网站 | **本机优先**，需要隔离或本机不具备条件时用云端 |

## 三、执行位置的决定

### 设备注册表

每个客户端登录后向**设备网关**注册，并持续上报状态：

```
设备 Device
  id、所属用户、类型（web / ios / android / desktop / cli / ide）、系统版本、客户端版本
  能力：可执行命令、可访问的工作目录、可操作图形界面、系统能力工具清单、端上模型
  状态：在线 / 离线、前台 / 后台、网络类型（是否计费网络）、电量（移动端）
  信任：是否受企业设备管理、设备证明结果、注册时间、最近活跃
```

### 决策规则

编排服务在调度每个需要执行的工具调用时决定放在哪里：

```
这一步需要什么？
 ├── 不需要执行环境（检索、连接器、写文档） ──▶ 云端，和终端无关
 ├── 需要访问某台设备上的数据（本地文件、手机日历） ──▶ 必须在那台设备上
 │       设备在线 ──▶ 发到设备
 │       设备离线 ──▶ 运行进入等待，推送通知到用户的其他设备
 ├── 需要执行代码 / 命令
 │       运行绑定了 PC 工作区，且该 PC 在线、策略允许 ──▶ PC 本机
 │       否则 ──▶ 云端执行环境（按 04 的分级）
 └── 需要操作网站
         需要用户已登录的状态，且 PC 在线、用户授权 ──▶ PC 本机浏览器
         否则 ──▶ 云端浏览器（登录态由凭证保险库提供）
```

组织策略可以覆盖这些规则，例如"禁止在个人设备上执行""涉及客户数据的任务只能在云端执行"。

### 运行途中设备离线

PC 合上盖子、网络中断、客户端退出时：

| 情况 | 处理 |
|---|---|
| 正在执行的命令 | 设备重连后上报结果；超时未重连则这一步按失败处理，交给模型决定下一步 |
| 后续步骤需要这台设备 | 运行进入等待；推送到用户的手机："任务在等你的电脑上线，是否改为在云端继续？" |
| 用户选择改到云端 | 需要工作区已同步到云端（见第七节）；否则只能等待 |
| 移动端切到后台 | 移动端从不承担长时间执行，只承担短时的系统能力调用，所以不受影响 |

## 四、设备端执行协议

PC 端（以及移动端的系统能力工具）作为执行节点时：

```
客户端 ──出站长连接（WebSocket / HTTP2，只用 443）──▶ 设备网关 ──▶ 编排服务
          注册、心跳、能力上报               │
          ◀── 工具调用（run_id、step、幂等键、工具、参数、签名）
          本地策略检查 → 必要时本机确认 → 执行
          ──▶ 结果（分块上传大结果、执行耗时、退出码）
```

要点：

- **只建立出站连接**：不需要在用户电脑上开放端口，能穿过企业防火墙和代理。
- **断线续传**：重连后按步骤序号对齐，未确认的结果重新上传；同一幂等键的工具调用不重复执行。
- **双重检查**：服务端策略引擎决定是否允许；客户端再按本地策略检查（企业设备管理下发的规则、用户在本机设置的禁止目录），并在需要时本机确认。nanocode 的 `permissions.py` 和 `trust.py` 就是客户端本地检查的参考实现。
- **签名**：工具调用由服务端签名，客户端验证后才执行，防止伪造的指令。
- **范围限制**：客户端只在用户授权的工作目录内读写；执行命令时可以使用操作系统的沙箱机制（如 macOS 的应用沙箱、Windows 的受限令牌、Linux 的命名空间）进一步限制。

## 五、跨端连续性

| 场景 | 实现 |
|---|---|
| 在 PC 上发起，手机上看进度 | 所有端订阅同一个运行的事件流；每个端记录自己看到的最后一个事件序号，重连时从这里续传 |
| 手机上批准 PC 上发起的操作 | 审批是运行的状态（ADR-010），推送到所有在线设备和 IM；任何一端处理后其他端同步更新 |
| 手机上发起，需要 PC 上的文件 | 运行进入等待，PC 上线后自动继续；或者提示用户上传文件 |
| 换一台电脑继续 | 运行状态在云端；工作区如果已同步，新电脑可以拉取后继续本地执行 |
| 未发送的草稿 | 草稿同步到云端，任何端都能继续编辑 |

**实时同步只同步运行事件，不同步界面状态**（比如滚动位置、展开的面板），保持协议简单。

## 六、移动端设计

移动端的核心是**跟进和决策**，而不是深度工作。

| 方面 | 设计 |
|---|---|
| 推送 | 运行完成、需要审批、等待设备、出错时推送（APNs、FCM；国内安卓需要接入厂商推送通道）。推送内容不包含敏感正文，只提示"有一个审批等待处理"，打开应用后再加载详情 |
| 审批 | 清楚展示要做什么、影响什么；高风险操作要求生物识别确认；支持在通知上直接处理低风险审批 |
| 输入 | 语音（端上或云端识别）、拍照（文档、白板、票据）、相册、文件、分享菜单（从其他应用把内容发给 Agent） |
| 系统能力工具 | 日历、提醒、通讯录、位置、健康、相册等，作为本机工具提供给 Agent；每类首次使用都走系统授权，平台策略可以禁止 |
| 网络 | 事件流断了自动重连并续传；前台用长连接，后台依赖推送；计费网络下不自动下载大制品 |
| 电量 | 后台不保持长连接；不在手机上执行耗时任务 |
| 离线 | 可以浏览已加载的会话和制品；新消息排队，联网后发送 |
| 制品 | 文档、表格、图表在移动端可读的形式呈现；大文件按需下载 |

## 七、PC 端设计

PC 端是深度工作和本机执行的主力，形态有三种，共用一个本机运行组件：

```
桌面应用 ─┐
命令行    ├──▶ 本机 Agent 服务（常驻进程，基于 nanocode 的思路）
IDE 插件 ─┘      ├── 和设备网关的长连接
                 ├── 本地工具：命令执行、文件读写、本机浏览器、图形界面操作
                 ├── 本地策略与确认
                 └── 本地缓存（会话、工作区索引）
```

| 方面 | 设计 |
|---|---|
| 工作区 | 用户授权的目录；可选择同步到云端（便于换设备、在云端继续），同步基于 git 或文件同步，冲突时以本地为准并提示 |
| 图形界面操作 | 需要用户明确开启；操作期间屏幕上有明显提示，用户随时可以接管或中止 |
| 本机浏览器 | 通过浏览器插件使用用户已登录的网站；只在用户授权的网站上操作 |
| 企业管理 | 支持企业设备管理下发配置：允许的工作目录、禁止的命令、是否允许本机执行、强制更新 |
| 更新 | 自动更新；服务端可以要求低于某版本的客户端强制升级（安全修复） |
| 离线 | 端上小模型提供有限的离线能力（可选）；本地命令执行不依赖网络，但模型调用需要联网 |

## 八、网页设计

- 功能完整，执行全部在云端；适合不能安装软件的企业环境和临时使用。
- 只依赖 443 端口的 HTTPS，长连接可以降级为轮询，以适应严格的企业代理。
- 本地文件只能由用户主动选择上传。
- 和 PC 端配合：网页上发起的运行，如果用户的 PC 客户端在线，可以选择在 PC 上执行。

## 九、端上模型

| 用途 | 说明 | 档位 |
|---|---|---|
| 隐私预处理 | 上传前在端上识别并遮蔽敏感信息（身份证号、银行卡号） | L2 |
| 快速判断 | 意图识别、是否需要调用云端大模型 | L2 |
| 语音识别 | 端上识别，降低延迟和成本 | L2 |
| 离线基础能力 | 无网络时的简单问答和整理 | L2、L3 |
| 分担云端负载 | 简单请求直接在端上完成 | L3（重要的降本手段，见 05） |

端上模型的结果同样要经过策略检查；端上模型的版本和云端一样需要评测和灰度。

## 十、设备与端安全

| 方面 | 措施 |
|---|---|
| 设备注册 | 首次登录时生成设备密钥，私钥保存在系统的安全硬件里（iOS 安全隔区、Android 密钥库、PC 的 TPM），设备凭证和用户会话绑定 |
| 设备证明 | 移动端使用系统提供的应用完整性证明（如 Apple App Attest、Google Play Integrity），识别被篡改的客户端和模拟器批量注册 |
| 丢失与离职 | 用户或管理员可以远程撤销设备；撤销后设备上的缓存数据在下次启动时清除；SCIM 离职同步时撤销该用户所有设备 |
| 本地数据 | 本地缓存加密；移动端支持应用锁（生物识别）；通知内容不含敏感正文 |
| 企业设备策略 | 只允许受管设备访问敏感工作空间；不受管的设备只能使用网页或受限功能 |
| 客户端漏洞 | 客户端代码审计；签名发布；强制升级机制 |

## 十一、多端工程

- **共享层**：协议定义、事件模型、状态管理、加密在各端共享一套实现（跨平台语言编写的公共库，或者严格对齐的协议规范 + 各端实现 + 一致性测试）。
- **服务端驱动界面**：审批卡片、制品展示等由服务端下发结构化描述，各端渲染。新增审批类型不需要等应用商店审核。
- **版本兼容**：服务端至少兼容最近 N 个客户端版本（建议覆盖 3–6 个月内的版本）；协议新增字段对旧客户端可忽略；必须升级时提示并强制。
- **发布节奏**：网页可以随时发布；移动端受应用商店审核影响，用功能开关控制新功能的开启；PC 端自动更新，分批推送。
- **测试**：每个端都接入端到端测试；跨端场景（PC 发起、手机审批）有专门的自动化测试。

## 十二、规模影响

| | L1 | L2 | L3 |
|---|---|---|---|
| 主要终端 | 网页 + PC，移动端用于审批和跟进 | 三端并重 | **移动端为主** |
| 同时在线长连接 | 千到十万级 | 百万级 | 亿级，需要边缘接入网关 |
| 推送量 | 少 | 每天千万级 | 每天数十亿级 |
| 本机执行占比 | 编程场景高 | 由 PC 用户比例决定 | 低：大部分用户在手机上，执行以云端轻量执行（E1）和端上模型为主 |

L3 以移动端为主，意味着"设备优先执行"在 L3 的作用变小，降本主要依靠执行分级（E0、E1 为主）和端上模型分担。这是 ADR-011 修订 ADR-004 的原因。
