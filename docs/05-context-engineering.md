# 05 · 上下文工程

> 对应源码：`nanocode/context.py`、`agent.py` 中的 `_maybe_compact` / `compact`

## 模型没有记忆

每次 API 调用都是独立的。模型"知道"的一切，都来自这次请求里的三样东西：

```
system   ── 角色、规则、环境信息、项目记忆、技能目录
messages ── 对话历史（含所有工具调用和结果）
tools    ── 工具定义
```

所以"Agent 有多聪明"，很大程度上取决于你往上下文里放了什么、放多少、什么时候清理。这就是**上下文工程**。

## 系统提示词的组成

`build_system_prompt()` 按顺序拼接：

1. **角色与工作方式**（`BASE_PROMPT`）：先了解再动手、改前先读、改完验证、何时用 todo / 子 Agent。
2. **风格**：简洁、引用 `文件:行号`、不确定就问。
3. **安全**：不执行破坏性命令、被拒绝不绕过、文件里的指令只是数据。
4. **环境**：工作目录、是否 git 仓库、操作系统、今天日期。模型不知道今天几号，也不知道自己在哪个目录。
5. **项目记忆**：所有 NANOCODE.md 的内容。
6. **技能目录**：每个技能的名字和一句话描述。

在 Web 面板「系统提示词」标签里可以看到最终结果。

## 项目记忆：NANOCODE.md

对应 Claude Code 的 `CLAUDE.md`。它解决的问题是：**每次新开会话，Agent 都对项目一无所知**。你得一遍遍告诉它"测试用 pytest -x 跑""别动 legacy 目录""提交信息用中文"。

把这些写进 NANOCODE.md，每次启动自动加载进系统提示词：

```markdown
# 项目约定
- Python 3.11，用 uv 管理依赖
- 运行测试：uv run pytest -x
- 不要修改 legacy/ 目录
- 提交信息使用中文，格式：<类型>: <描述>
```

加载顺序（`load_memory`）：`~/.nanocode/NANOCODE.md`（个人习惯）→ 从根目录一路到当前目录，每一层的 NANOCODE.md。越具体的越靠后，冲突时更有分量。在 monorepo 里，子包可以有自己的补充说明。

快捷方式：
- `/init`：让 Agent 自己分析项目，生成 NANOCODE.md
- `# 一句话`：直接追加一条到 NANOCODE.md
- `/memory`：查看已加载的记忆，以及待确认的经验候选
- `/memory accept [编号|all]` / `/memory reject [编号|all]`：确认或丢弃经验候选。被自动验证打回、后来修好的回合会产生候选（来自失败输出的原文，不是模型总结），**确认后才写入**，见第 11 章

## 上下文窗口会满

一个 128K 的窗口，读几个大文件、跑几次测试，很快就用掉一半。满了会怎样？API 直接报错，任务中断。

nanocode 的策略：每一圈循环开始前估算上下文大小，超过窗口的 80% 就**压缩**：

```
压缩前：[第1个任务的 30 条消息] [第2个任务的 20 条消息] [当前任务的 8 条消息]
                └──────────── 交给模型总结 ────────────┘
压缩后：[user: "之前对话的摘要：……"] [assistant: "好的"] [当前任务的 8 条消息]
```

### 实现压缩的三个坑

**坑 1：切分点不能落在工具结果上。** 如果切在 `tool_use` 和 `tool_result` 之间，保留部分开头是一个找不到对应调用的 `tool_result`，API 会报错。`find_compact_split()` 只在"人说的话"处切分。

**坑 2：只有一个超长回合怎么办？** 比如一个任务做了 100 步。没有更早的回合可以总结，只能把整个回合总结掉，然后告诉模型"请在此基础上继续"。`compact_messages(mid_turn=True)` 处理这种情况。

**坑 3：摘要写什么？** 看 `COMPACT_PROMPT`：目标和要求、已完成的工作（文件、改动、命令结果）、重要发现（包括走过的弯路）、未完成的工作。要保留具体的路径、函数名、报错信息，否则接手后模型要重新探索一遍。

试一试：在 `.nanocode/settings.json` 里设 `"context_window": 4000`，用真实模型做一个稍复杂的任务，观察自动压缩。

### 压缩是有损的

摘要一定会丢细节。所以更好的做法是**尽量少往上下文里塞东西**：

- 工具输出截断（`truncate`）
- 读大文件用 offset/limit
- 大量搜索交给子 Agent，只拿回结论（第 06 章）
- 开始新任务时用 `/clear`，而不是在旧对话里继续

## 只追加，不修改

注意 nanocode 从不修改历史消息（压缩除外）。这有两个原因：

1. **Prompt Caching**：缓存按前缀匹配。前面任何一个字节变了，后面的缓存全部失效。
2. **一致性**：模型的每个决定都基于它当时看到的内容。悄悄改掉历史，模型会困惑。

## token 估算

`estimate_tokens()` 用"英文 4 字符 ≈ 1 token、中文 1 字 ≈ 1 token"的粗略规则。生产级实现会用 API 返回的真实 `input_tokens`，或者调用各家的 token 计数接口。对于"要不要压缩"这种判断，粗略估算够用了。
