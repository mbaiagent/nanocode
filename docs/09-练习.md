# 09 · 练习

每道题都标明了要改的文件。改完记得跑 `python3 -m unittest discover -s tests`，最好也为你的改动加一个测试。

## 入门

**1. 读懂一次运行**
用 `--trace` 运行一次 Mock 模型，打开 `~/.nanocode/projects/<项目>/traces/*.jsonl`，或运行 `python3 verification/trace_stats.py`。数一数：循环转了几圈？模型调用了几次？哪些工具是并行执行的？

**2. 改工具说明，观察行为**
接入一个真实模型。把 `glob` 工具的 description 改成一句"找文件"，让 Agent "找出项目里所有的测试文件"。再改回来对比。说明写得好坏对模型行为的影响有多大？
（`tools/search.py`）

**3. 新厂商预设**
给 `PRESETS` 加一个你常用但没在列表里的厂商。
（`llm/__init__.py`）

## 进阶

**4. 新工具：list_dir**
实现一个只读的 `list_dir` 工具，以树形结构列出目录（限制深度，忽略 `IGNORED_DIRS`）。思考：它和 `glob` 有什么分工？description 怎么写才能让模型在正确的时候选它？
（`tools/search.py`、`tools/__init__.py`）

**5. 编辑前显示 diff**
在 default 模式下，`edit_file` 询问权限时，让用户看到修改前后的 diff。提示：Python 标准库有 `difflib`；权限询问回调目前只拿到 `target`，你需要决定如何把更多信息传给界面。
（`permissions.py`、`cli.py`、`web/static/index.html`）

**6. 更聪明的 bash 权限**
现在的 `bash(git status*)` 规则会被 `git status; rm -rf x` 绕过。改进 `_matches_any`：对 bash 命令先按 `;`、`&&`、`||`、`|` 拆分，**每一段**都命中 allow 才算允许，**任意一段**命中 deny 就拒绝。
（`permissions.py`）

**7. 用小模型做压缩**
允许在配置里指定一个单独的 `compact_model`，压缩时用它而不是主模型。
（`session.py`、`agent.py`）

**8. 撤销**
记录每次 `write_file` / `edit_file` 之前的文件内容，实现 `/undo` 命令撤销 Agent 最近一次修改。
（`tools/files.py`、`session.py`）

## 挑战

**9. 自定义子 Agent 类型**
仿照 Claude Code 的 `.claude/agents/`，支持在 `.nanocode/agents/<名字>.md` 里定义子 Agent：frontmatter 指定名字、描述、可用工具列表，正文是它的系统提示词。`task` 工具增加一个 `agent_type` 参数。
（`context.py`、`agent.py`、`tools/planning.py`）

**10. 检查点**
每一轮用户消息之前，给工作目录拍一个快照（可以用 git stash 或复制修改过的文件），实现 `/rewind` 回到任意一轮之前的状态（文件 + 对话）。

**11. MCP over HTTP**
实现 MCP 的 Streamable HTTP 传输，接入一个远程 MCP 服务器。
（`mcp.py`）

**12. 评测**
`evals/agent_tasks/` 已经有一个 13 任务的评测框架（参考实现；其中 T11–T13 专门设了陷阱，见第 11 章）。练习：先用两个不同的模型各跑 3 遍，比较成功率、平均步数和 token；然后只改一处（某个工具的 description、系统提示词里的一句话），再跑一遍，看分数怎么变。再给它加 2 个你自己设计的任务，注意让"参考答案能过、什么都不做过不了"（`tests/test_agent_eval.py` 会帮你检查）。改动先评测、再下结论，这才是优化 Agent 的正确姿势。

**13. 找漏洞**
`tests/test_security.py` 里记录了三个曾经真实存在的漏洞。试着再找一个：比如 `grep` 工具的 `glob` 参数、`bash` 工具的工作目录记忆、MCP 工具的权限匹配，有没有能绕过权限检查的写法？找到后先写一个失败的测试，再修。

**14. 找出分类器的漏洞**
`risk.classify_bash()` 是启发式的。试着找一条**会被误判成 `safe`** 的命令（提示：参数里的子命令、环境变量、别名、`git` 的各种选项）。找到后先写一个失败的测试加到 `tests/test_review_mode.py`，再收紧规则。方向永远是"宁可多问"。
（`risk.py`）

**15. 让越界的子 Agent 自动还原**
现在子 Agent 越界后，是把说明交还给它让它自己还原。改成系统自动还原：越界文件用 `review.remember()` 那样的办法在改动前记下原文，发现越界后直接写回。想想 bash 造成的越界怎么办——你有原文吗？
（`subcheck.py`、`review.py`、`agent.py`）

**16. 支持更多测试框架的证据提取**
`lessons.extract_evidence()` 只认 Python 风格的报错行（`FAIL`、`Error:`……）。给它加上 jest（`●` 开头的失败标题）和 `go test`（`--- FAIL:`）的识别，并为每种写测试。
（`lessons.py`）

**17. 验证命令按改动范围缩小**
现在 `verify` 每次都跑完整的检查命令。设计一个选项：只跑和本轮改动文件相关的测试（比如改了 `src/a.py` 就只跑 `tests/test_a.py`）。想想它会让 T12、T13 这类陷阱更容易还是更难被发现。
（`verify.py`、`agent.py`）
