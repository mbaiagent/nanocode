# 09 · 练习

每道题都标明了要改的文件。改完记得跑 `python3 -m unittest discover -s tests`，最好也为你的改动加一个测试。

## 入门

**1. 读懂一次运行**
用 `--trace` 运行一次 Mock 模型，打开 `.nanocode/traces/*.jsonl`。数一数：循环转了几圈？模型调用了几次？哪些工具是并行执行的？

**2. 改工具说明，观察行为**
接入一个真实模型。把 `glob` 工具的 description 改成一句"找文件"，让 Agent "找出项目里所有的测试文件"。再改回来对比。说明写得好坏对模型行为的影响有多大？
（`tools/search.py`）

**3. 新厂商预设**
给 `PRESETS` 加一个你常用但没在列表里的厂商。
（`llm/__init__.py`）

## 进阶

**4. 新工具：list_dir**
实现一个只读的 `list_dir` 工具，以树形结构列出目录（限制深度，忽略 `IGNORED_DIRS`）。思考：它和 `glob` 有什么分工？description 怎么写才能让模型在正确的时候选它？
（`tools/search.py`、`tools/__init__.py`）

**5. 编辑前显示 diff**
在 default 模式下，`edit_file` 询问权限时，让用户看到修改前后的 diff。提示：Python 标准库有 `difflib`；权限询问回调目前只拿到 `target`，你需要决定如何把更多信息传给界面。
（`permissions.py`、`cli.py`、`web/static/index.html`）

**6. 更聪明的 bash 权限**
现在的 `bash(git status*)` 规则会被 `git status; rm -rf x` 绕过。改进 `_matches_any`：对 bash 命令先按 `;`、`&&`、`||`、`|` 拆分，**每一段**都命中 allow 才算允许，**任意一段**命中 deny 就拒绝。
（`permissions.py`）

**7. 用小模型做压缩**
允许在配置里指定一个单独的 `compact_model`，压缩时用它而不是主模型。
（`session.py`、`agent.py`）

**8. 撤销**
记录每次 `write_file` / `edit_file` 之前的文件内容，实现 `/undo` 命令撤销 Agent 最近一次修改。
（`tools/files.py`、`session.py`）

## 挑战

**9. 自定义子 Agent 类型**
仿照 Claude Code 的 `.claude/agents/`，支持在 `.nanocode/agents/<名字>.md` 里定义子 Agent：frontmatter 指定名字、描述、可用工具列表，正文是它的系统提示词。`task` 工具增加一个 `agent_type` 参数。
（`context.py`、`agent.py`、`tools/planning.py`）

**10. 检查点**
每一轮用户消息之前，给工作目录拍一个快照（可以用 git stash 或复制修改过的文件），实现 `/rewind` 回到任意一轮之前的状态（文件 + 对话）。

**11. MCP over HTTP**
实现 MCP 的 Streamable HTTP 传输，接入一个远程 MCP 服务器。
（`mcp.py`）

**12. 评测**
写 10 个小任务（比如"修复这个函数里的 bug，并让测试通过"），每个任务配一个自动判定脚本。用不同的模型跑一遍，统计成功率、平均步数、token 用量。这就是 Agent 评测（eval）的雏形。改一处提示词或工具说明后再跑一遍，看分数变化 —— 这才是优化 Agent 的正确姿势。
