# 00 · 学习路线

## 目标

学完之后你应该能：

1. 用自己的话讲清楚"Agent 和普通聊天机器人的区别"
2. 不看代码，在白纸上画出一个编程 Agent 的架构图
3. 说出 Claude Code 的每个核心功能（权限模式、CLAUDE.md、/compact、Hooks、子 Agent、Skills、MCP）分别解决什么问题、大致怎么实现
4. 给 nanocode 加一个新工具、接一家新模型、写一个 Hook，并知道改哪些文件

          │        │否                                             │

## 推荐的学习顺序（7 个晚上）

| 天 | 做什么 | 读什么 |
|---|---|---|
| 1 | 用 Mock 模型跑 Web 界面，盯着「循环时间线」和「上下文」两个标签看 | 01 章 + `agent.py` |
| 2 | 读消息格式和两个 provider，对比同一段对话在两种协议下的样子 | 02 章 + `messages.py`、`llm/` |
| 3 | 接入一个真实模型（推荐 DeepSeek / 千问 / Claude），让它帮你改一个小项目 | 03 章 + `tools/` |

## 用 Web 面板学习的方法

`python3 -m nanocode --web` 打开后，右侧是"透视面板"：

- **循环时间线**：每张卡片是循环的一圈。看 `stop_reason` 从 `tool_use` 变成 `end_turn`，就是循环结束的那一刻。
- **上下文**：下一次要发给模型的完整 messages。注意 `tool_result` 是以 `user` 身份出现的。
- **系统提示词**：写一个 NANOCODE.md，再来这里看，它被拼进去了。
- **工具定义**：模型看到的就是这些 JSON。试着改一个工具的 description，观察模型行为的变化。
- **事件流**：CLI、Web、trace 都只是这些事件的订阅者。

另外 `/learn` 页面是一份交互式的架构讲解，里面有一个"单步模拟器"，可以一步一步看 messages 数组如何增长。

## 带着这些问题去读代码

- 模型怎么"知道"有哪些工具可用？（提示：`tools` 参数，不是系统提示词）
- 工具执行出错时，Agent 为什么不崩溃？错误信息去了哪里？
- 如果模型一次返回 3 个工具调用，执行顺序是怎样的？结果顺序呢？
- 用户按 Ctrl-C 时，已经发出的 `tool_use` 怎么办？（提示：消息列表必须保持合法）
- 压缩上下文时，为什么切分点不能落在 `tool_result` 上？
- 子 Agent 的工具调用要不要经过权限检查？它能看到主对话吗？
