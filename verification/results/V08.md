## 发现的问题

**候选 issue：allow 规则被 `cd <dir> &&` 前缀绕过（fnmatch 整串匹配）**

- 复现：项目 `.nanocode/settings.json` 的 allow 列表含 `bash(python3 -m unittest*)`；模型实际执行的命令是 `cd /tmp/…/examples/project && python3 -m unittest test_calc -v`（`cd` 前缀是模型自己加的）；`fnmatch.fnmatchcase(整串, "python3 -m unittest*")` 返回 False → 走 ask → 非交互 -p 模式无人可问 → deny。
- 实际结果：TASKS.md V08 检查点 6 预期"命中 allow 规则"，实际 5 次 bash（含 `{"command": "pwd", "mode": "allow"}`）全部被拒；模型只好放弃运行测试，改由验证者手动跑。
- 预期结果：allow 规则应对"实质执行的命令"生效，或拒绝提示如实说明"allow 规则未命中（命令含 cd 前缀）"而不是笼统说"可用 allow 规则放行"（规则明明配了）。
- 涉及文件：`nanocode/permissions.py`（`_matches_any` 的 fnmatch 整串匹配）；`nanocode/permissions.py` 第 120 行的 deny 提示文案。
- 备注：用 `--mode bypass` 可绕过（V02 验证过），所以这是 papercut 级别，不是阻断；但 `-p` 非交互场景下模型无法"自己加 allow"，属于真实可用性问题。
