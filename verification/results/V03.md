## 测试链路（重要）

浏览器跑在远端租赁 VM，连不上测试机回环地址。最终链路：
`浏览器 → VPS nginx:443（SNI v03test.104.194.92.198.nip.io，proxy_buffering off）→ VPS 本机 mock（127.0.0.1:18771）`
nginx 改写 Host/Origin 为 `127.0.0.1:18771` 以通过新版校验；自签名证书，浏览器端绕过警告。

## 关键输出

首轮曾出现 4 项失败（2/3/4/7），根因逐一排除，均在测试链路侧，不在 nanocode 本体：

1. 自写反向代理用 `resp.read(8192)` 转发 SSE——SSE 永不结束，`read` 阻塞到上游关闭，
   浏览器永远收不到事件。改为 `fp.read1()` + 每段 flush 后，curl 实测事件实时到达
   （含 permission_request）。
2. 经 Cloudflare 隧道（quick tunnel）时，即使改成 `Transfer-Encoding: chunked`，
   edge 依然缓冲 SSE（40 秒 0 字节；对照：直连代理同时段 50 行事件）。改走 VPS
   nginx 直连后，SSE 历史重放与实时事件均正常。

nanocode 本体（含前端 EventSource 渲染、权限卡片、中断按钮）在此链路上 8/8 通过。

## 发现的问题

1. **已提 Issue #3**：SSE 用 `EventSource("/api/events?token=" + …)` 把 32 位 API token
   放进 URL 查询参数，会进 nginx access log 与浏览器历史。
   https://github.com/mbaiagent/nanocode/issues/3
2. **待提**：`refreshState()` 只在 `!s.busy` 时 `setBusy(false)`，忙时不同步——刷新页面
   后 UI 显示空闲而服务端实际忙着，发消息被拒（"Agent 正在工作"），UI 与服务端状态不一致。
   位置：`nanocode/web/static/index.html` 的 `refreshState()`，应为 `setBusy(s.busy)`。
