### 执行的命令

```bash
python3 examples/rag_eval/run_eval.py                                   # 检查点 1
NANOCODE_API_KEY="$OPENROUTER_API_KEY" python3 examples/rag_eval/run_eval.py \
    --embed-provider "" --embed-base-url https://openrouter.ai/api/v1 \
    --embed-model qwen/qwen3-embedding-8b --verbose                     # 检查点 2、3
```

脚本没有 `--embed-api-key` 参数。`--embed-provider` 只能选预设厂商，OpenRouter 不在预设里，所以 Key 只能通过通用回退变量 `NANOCODE_API_KEY` 传入。第一次尝试没有带 Key，返回 `HTTP 401: No cookie auth credentials found`，脚本如实打印"向量化失败"并跳过向量行。

### 评测脚本的一处修正（重要）

第一版运行的语料不一致：grep 基线用的是 `load_corpus` 收集的 `docs/` 下所有 Markdown（含 `docs/platform/` 的 15 个文件，共 32 篇），而 BM25 和向量用的是 `DocIndex` 的 `docs/*.md`（只含顶层 17 篇）。两边比的不是同一批文档，第一版的数字作废。

修正：`run_eval.py` 增加 `CORPUS_GLOB = "docs/*.md"`，`load_corpus` 和 `DocIndex` 共用同一个 glob，语料统一为顶层 17 篇、221 个块。修正后重跑两条命令，下面的表格就是这次的结果。

### 结果（语料 17 篇文档、221 个块，22 道题）

| 方法 | recall@1 | recall@3 | recall@5 | MRR |
|---|---|---|---|---|
| grep-原句 | 0% | 0% | 0% | 0.00 |
| grep-关键词 | 0% | 32% | 55% | 0.25 |
| bm25 | 36% | 91% | 95% | 0.61 |
| vector（qwen3-embedding-8b） | 77% | 91% | 100% | 0.84 |
| hybrid（RRF 融合） | 73% | 95% | 95% | 0.84 |

### 怎么解读

- **向量检索明显提升了第 1 名的准确率**：recall@1 从 BM25 的 36% 提升到 77%，MRR 从 0.61 提升到 0.84。题目是转述、不是原文用词时，语义匹配比关键词强得多。
- **混合检索在 recall@3 上最好（95%）**，但 recall@1 比纯向量低（73% vs 77%）。RRF 融合在这 22 道题上只在前 3 名的覆盖上略胜。
- **样本很小**：22 道题，差 1 题就是 4–5 个百分点。这些数字只能说明"在这个语料和这批题上，向量明显优于 BM25"，不能推广成通用结论。
- **和更早的记录不能直接比较**：2026-10-13 的基线（bm25 recall@3 91%）是在 11 篇、102 块上测的，语料已经变了。

### 发现的问题

1. **评测语料不一致**（已修正）：见上文。这是评测脚本的缺陷，不是检索本身的问题；按旧语料得出的第一版数字已作废。
2. **评测脚本缺少 API Key 参数**：`--embed-provider` 只能用预设厂商，接入 OpenRouter 这类通用中转时要靠 `NANOCODE_API_KEY` 回退。建议加一个 `--embed-api-key-env` 参数。
3. **旧版文档过时**：`verification/TASKS.md` 里写"OpenRouter 目前不一定提供 embedding 接口"，现在 OpenRouter 提供 33 个 embedding 模型，接口与 OpenAI 兼容。
