    第 5 节
    
上下文窗口：会满，所以要压缩

    
Agent 每走一步，工具结果都会追加进上下文。读几个大文件、跑几次测试，窗口很快就用掉一大半。nanocode 在每圈循环开始前检查：超过 80% 就把旧回合交给模型写成摘要，保留最近一个回合原样不动。

    源码：nanocode/context.py · compact_messages、find_compact_split

切分点只能落在"人说的话"上
如果切在 tool_use 和 tool_result 之间，保留下来的第一条是找不到对应调用的工具结果，API 会直接报错。这是实现压缩时最常见的 bug。

    
摘要要写具体
目标、已改的文件、跑过的命令和结果、走过的弯路、下一步。路径和报错原样保留，否则接手后又得重新探索一遍。

    
能不进上下文就不进
压缩是有损的。更好的办法是输出截断、分段读文件、大搜索交给子 Agent、换任务时 /clear。

    第 7 节
    
开始动手

    
不需要 API Key 就能跑：默认的 Mock 模型会按固定剧本演示一遍完整循环。Web 界面右侧的面板能实时看到每一圈循环和完整上下文。

  

  

    

      
跑起来

      
python3 -m nanocode --web

      
python3 -m unittest discover -s tests

      
然后打开 http://127.0.0.1:8765

    

    

      
接真实模型

      
nanocode --provider deepseek --model deepseek-chat

      
nanocode --provider custom --protocol openai --base-url https://你的地址/v1 --model 模型名

      
Key 放在对应环境变量里，例如 DEEPSEEK_API_KEY。
